# 01 - Data Model

**Purpose:** the single source of truth for persisted data: SQLite tables, field names, enums, IDs, file layout and staleness rules.
**Depends on:** `00-master-index.md`.
**Used by:** every other spec. Connection handling and migrations are owned by `04`; endpoint shapes by `02`.

---

## 1. Conventions

| Topic | Rule |
|-------|------|
| Database | SQLite, one file. `PRAGMA foreign_keys = ON`, WAL journal mode (set by `04`). |
| Primary keys | `TEXT`, format `{prefix}_{16 lowercase hex chars}`, generated by the backend. Never auto-increment integers. |
| Timestamps | `TEXT`, ISO 8601 in UTC with `Z` suffix, e.g. `2026-11-06T09:30:00Z`. Fields ending `_at`. |
| Booleans | `INTEGER` 0 or 1. Fields starting `is_`. |
| Enums | `TEXT` with a `CHECK` constraint listing allowed values (section 3). |
| JSON columns | `TEXT` holding JSON; names end `_json`. Used only where flexibility is needed. |
| Money | Not stored (estimates are computed). Rates are `REAL` in the configured currency (default INR). |
| Lengths and areas | `REAL`, feet (`_ft`) and square feet (`_sqft`). |
| Boxes | Four `REAL` columns `box_x, box_y, box_w, box_h`, normalized 0-1, origin top-left of the photo. Constraint: `0 <= x`, `0 <= y`, `w > 0`, `h > 0`, `x + w <= 1`, `y + h <= 1` (validated in code with a small tolerance of 0.001, then clamped). |
| File paths | Stored **relative to the storage root** with forward slashes. Never absolute. |
| Deletion | Hard delete with `ON DELETE CASCADE` unless stated. |
| Schema changes | Prototype: tables created at startup if missing. A `schema_version` row in `app_meta` is checked; no migrations needed for the prototype. |

| Entity | Prefix |

## 2. Entity relationship overview

```
projects 1---* photos 1---* components *---1 (optional) detected_components
projects 1---* variants 1---* selections *---1 components
components 1---0..1 component_measurements
projects 1---* generations (each for a variant and a photo)
projects 1---* project_rates
projects 1---* reports
projects 1---* stage_runs
app_meta (key/value)
```

## 3. Enumerations

### 3.1 `component_type` (canonical vocabulary)

| Value | Meaning | Typical catalogue support |
|-------|---------|---------------------------|
| `wall` | Main wall surface | yes |
| `window` | Window opening | no (used for area deductions and prompt context) |
| `door` | Door opening | no (same) |
| `balcony` | Balcony structure/slab edge | yes (limited finishes, defined in 09) |
| `railing` | Balcony or staircase railing | yes |
| `pillar` | Pillar or column | yes |
| `parapet` | Parapet wall | yes |
| `gate` | Gate area | yes |
| `roof_edge` | Roof edge or fascia | yes |
| `other` | Anything else detected (pavement, vehicles, trees, etc.) | never |

Support is **not stored**. It is derived by checking the catalogue's component-type compatibility (`09`) when components are read. New types are added by extending this enum (a `CHECK` update plus catalogue entries); no other structural change is needed.

### 4.5 `components` (the working set the user edits)

| Column | Type | Notes |
|--------|------|-------|
| `id` | TEXT PK | `cmp_...` |
| `project_id` | TEXT NOT NULL | FK CASCADE |
| `photo_id` | TEXT NOT NULL | FK CASCADE |
| `type` | TEXT NOT NULL | `component_type` |
| `label` | TEXT NOT NULL | 1-120 chars. Used in the redesign prompt and the report. |
| `box_x`, `box_y`, `box_w`, `box_h` | REAL NOT NULL | Normalized |
| `confidence` | REAL NULL | Copied from detection; NULL for user-created |
| `origin` | TEXT NOT NULL | `component_origin` |
| `source_detection_id` | TEXT NULL | FK `detected_components.id` ON DELETE SET NULL |
| `is_locked` | INTEGER NOT NULL DEFAULT 0 | 1 if user created or edited it |
| `created_at`, `updated_at` | TEXT NOT NULL | |

**Rules**
- AI-origin components are created unlocked (`is_locked = 0`).
- Any user edit (type, label or box) sets `is_locked = 1`. User-created components are locked from the start.
- Re-detection deletes only unlocked AI components of that photo, then inserts new ones. Locked components are never touched.
- Index: `components(project_id, photo_id)`.

### 4.9 `component_measurements`

| Column | Type | Notes |
|--------|------|-------|
| `id` | TEXT PK | `mea_...` |
| `component_id` | TEXT NOT NULL UNIQUE | FK CASCADE. One measurement per component. |
| `input_mode` | TEXT NOT NULL | `measurement_input_mode` |
| `width_ft`, `height_ft` | REAL NULL | Required when mode = `dimensions` |
| `length_ft` | REAL NULL | Required when mode = `length` |
| `area_sqft` | REAL NULL | Gross area. Direct input when mode = `area`; computed (`width x height`) when mode = `dimensions`; NULL when mode = `length`. |
| `deduction_sqft` | REAL NOT NULL DEFAULT 0 | Openings to subtract from a gross area (e.g. windows on a wall). Net area = `max(0, area_sqft - deduction_sqft)`. |
| `uncertainty_pct` | REAL NOT NULL | Default 15 for `user`, 25 for `ai_estimate`. Editable. Range 0-100. |
| `source` | TEXT NOT NULL | `measurement_source` |
| `note` | TEXT NULL | Free text, max 200 chars |
| `created_at`, `updated_at` | TEXT NOT NULL | |

**Rules**
- An AI-estimated measurement is created only for components that have no measurement. It never replaces a `user` measurement.
- When the user edits any field of an `ai_estimate` measurement, `source` becomes `user`.
- Editing a component's box or type deletes its `ai_estimate` measurement (it is now outdated) but keeps a `user` measurement.
- Allowed inputs: positive numbers, max 1000 for lengths/areas on each field, `deduction_sqft >= 0`.
- For mode `length`, `width_ft`, `height_ft` and `area_sqft` are all NULL. For mode `area`, `width_ft`, `height_ft` and `length_ft` are all NULL. For mode `dimensions`, `length_ft` is NULL.

## 5. Derived values (never stored)

| Value | Derivation |
|-------|-----------|
| `supported` (per component) | Catalogue has at least one material compatible with `type` |
| `is_stale` (per generation) | `generations.input_fingerprint` differs from the variant's current fingerprint (section 7) |
| Net area, quantities, costs, totals | Computed by the estimation service from measurements, selections, catalogue and effective rates (`11`) |
| Effective rates | Catalogue defaults overlaid by `project_rates` |

## 6. File storage layout

All paths relative to `STORAGE_ROOT` (config, `04`).

```
projects/{project_id}/original/{photo_id}.{ext}      uploaded photo, as received (orientation applied on read)
projects/{project_id}/generated/{generation_id}.png  redesigned image
projects/{project_id}/reports/{report_id}.pdf        PDF report
```

- File names are always built from backend-generated IDs, never from client input.
- The SQLite file lives outside the storage root (`DATABASE_PATH`, default `data/app.db`).
- Working copies sent to AI models are created in memory (`05`) and not stored.
- Deleting a project deletes its whole `projects/{project_id}/` directory and its database rows. Deleting a photo, generation or report removes its file.

## 7. Staleness and invalidation rules

Cost and quantity estimates are computed live, so they cannot be stale. Only generations and AI-estimated measurements depend on other data.

### 7.1 Generation fingerprint

The fingerprint is a hash over:
1. `photo_id`
2. For every component in the variant that has a selection, sorted by component ID: `component_id`, `type`, `label`, box values rounded to 3 decimals, `material_id`, canonical `params_json`
3. `extra_instructions` (empty string if none)
4. The prompt template version (constant defined in `10`)

`is_stale = (generation.input_fingerprint != current fingerprint)`. The exact serialization is defined in `10`; this file defines only what it covers.

### 7.2 Effects of user actions

| User action | Effect |
|-------------|--------|
| Edit component box, type or label | Generations of variants using it become stale (fingerprint changes). Its `ai_estimate` measurement is deleted. Selections whose material is no longer compatible with the new type are deleted (response warns, `02`). |
| Delete component | Its selections and measurement are deleted (cascade). Generations become stale. |
| Add component | No effect until it receives a selection. |
| Change or add a selection | Generations of that variant become stale. Estimates update immediately (computed live). |
| Change a rate or wastage override | Only estimates change. Generations unaffected. |
| Edit or add a measurement | Only estimates change. Generations unaffected. |
| Re-run detection | Unlocked AI components replaced. Generations become stale if any used component changed. |
| Delete photo | All components, selections, measurements and generations for it are deleted. Reports remain. |
| Rename variant | No effect. |

Stale generations stay visible and downloadable, labelled "outdated". The user chooses whether to regenerate. Approval is bound to the generation record; if it is stale, the UI shows approval as outdated and the report warns (`12`).

## 8. Integrity and concurrency rules

- A project may have at most one `generations` row with status `running` at a time. A second request returns a conflict (`02`). Enforced in code.
- At startup, any `stage_runs` or `generations` left in `running` state older than the longest AI timeout is marked `failed` with error code `INTERRUPTED` (owned by `04`).
- Writes within one request use one transaction. AI calls happen **outside** any open transaction.
- Cascades handle all child deletion; services never delete child rows manually except where this file requires selective deletion (type change, re-detection).

## 9. Acceptance criteria

- Creating a project produces one `projects` row, one `variants` row (`Design 1`) and the project's storage directory.
- Re-running detection after the user edits one component leaves that component unchanged and replaces the others.
- Deleting a project leaves no rows in any table and no files on disk for it.
- A unique-constraint violation (variant name, selection, measurement) surfaces as a `CONFLICT` error, never a 500.
- All box values read from the database satisfy the box constraint in section 1.
